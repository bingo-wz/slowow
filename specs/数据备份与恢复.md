# 慢慢：数据备份与恢复

更新时间：2026-11-07

## 手动备份

在已配置 `manman-server` SSH 别名的开发电脑上，从项目根目录运行：

```sh
./tools/backup-server.sh
```

脚本先备份服务器的 PostgreSQL 数据库快照，再备份私有附件，分别用开源工具 `age` 加密后保存到 `~/Library/Application Support/manman/backups/`。脚本需要本机安装 `age`、可使用公钥登录服务器，且该账号能够无交互地运行指定的 `sudo` 命令。一次备份结束后会显示备份目录。

恢复密钥默认位于 `~/Library/Application Support/manman/backup-identity.txt`。**请把这个文件另外保存在安全位置，勿发到聊天、代码仓库或公开网盘；丢失它将无法解密备份。** 加密备份和密钥应分别保管。当前没有自动备份或异地副本，需定期手动备份，并将加密备份复制到另一台设备或可信存储。

MiMo API Key、授权码摘要和两个识别账号的绑定不包含在这份备份中；更换服务器恢复时需重新安全配置和绑定，不能把密钥或授权码放进备份说明或聊天。

## 验证恢复

2026-11-07 已将一次测试备份解密并恢复到本机独立 PostgreSQL 17 测试库，核对三张表和三条账号隔离策略，并验证附件归档可解密读取。这个演练不代表未来所有备份都一定可恢复，应定期重复。

恢复操作应先在隔离测试环境进行，核对账号隔离、记录及图片完整后，再制定正式恢复步骤；不要直接覆盖正在使用的数据库或附件目录。数据库和附件必须使用同一次备份，完整恢复还需要服务配置、CloudBase 身份环境及妥善保管的恢复密钥。CloudBase 登录账号本身不包含在这份业务数据备份中。
